# Airstrike — мод NeoForge для Minecraft 1.21.1 (модпак «All of Create Aeronautics»)

Кинематографичные и при этом реалистичные удары: дрон-камикадзе (как Shahed-136), крылатая ракета,
B-2 с бетонобойной бомбой, залпы с разбросом, МБР с ядерной боевой частью; пульт наведения с биноклем,
точное наведение на всё, куда смотрит игрок (блоки, мобы, игроки, летательные аппараты Create Aeronautics),
свой 3D-звук с Доплером. Репозиторий: https://github.com/zentixua/airstrike (публичный).
Что умеет мод для игрока — README.md; проект ядерного удара и отступления от него — docs/DESIGN-nuke.md.

Здесь — только то, что нужно в каждой сессии. Устройство пакетов и подводные камни по областям — в `.claude/rules/`
(список в конце): файл области подгружается сам, когда Claude открывает её файлы инструментами Read, Edit или Write.
Читаешь код через Bash или планируешь работу, ещё не открыв файлов, — прочитай файл правил области сам. Новое правило
или камень — в файл своей области; сюда — только общее для всех сессий.

## Люди и правила общения
- Автор/хост: **Артём**, в игре **ZentixUA**. Друзья: **ENOTzRPG**, **WallyFillmark**.
- Общаемся по-русски, кратко и по делу.
- **Не управлять компьютером пользователя** (никакого computer-use, кликов в игре). Всё готовим так,
  чтобы Артёму оставалось только запустить игру: мод приходит в неё выпуском и PR сборки (автообновление).
- **Минимум просьб «проверь в игре»** — это мешает игре. Проверяем сами: юнит-тесты, GameTest, клиент без окна
  (`tools/client_scenario.sh`), после игры — `tools/logscan.py`.
- Не удалять миры/сейвы/файлы пользователя. Лишнее — переносить в сторону (`deploy.sh` кладёт в `airstrike-backup/`).
- Качество важнее скорости: перед сдачей — сборка, тесты, GameTest, ревью диффа.
- **Доводить до конца без вопросов**: когда работа готова и проверена (сборка, тесты, GameTest), самому влить свой PR
  (после зелёного CI, чистого независимого ревью и вердикта координатора) и довести мод до игры: `tools/deploy.sh` —
  в инстанс без автообновления сборки, в инстанс с ним мод приходит выпуском и PR сборки. Артём должен застать мод
  готовым к игре, а не список шагов для себя. Спрашивать только то, что меняет цель или чего нельзя отменить.
- Публичные шаги (релиз на GitHub, Modrinth, YouTube) — только по прямому слову Артёма.

## Рабочий цикл
```sh
export JAVA_HOME=~/.var/app/org.prismlauncher.PrismLauncher/data/PrismLauncher/java/java-runtime-delta
cd mod && ./gradlew build                 # компиляция (-Xlint:all без предупреждений) и юнит-тесты
cd mod && ./gradlew runGameTestServer     # GameTest: сервер без окна с Create 6.0.10, Sable 2.0.5, Aeronautics 1.3.2
cd mod && ./gradlew :gm:runGmGameTestServer  # GameTest мода ведущего (без Create; ./gradlew build собирает оба мода)
cd mod && ./gradlew runScenarioSweep      # одни сценарии полёта, все зёрна (-PscenarioSeeds=N, по умолчанию 16;
                                          # -PscenarioOnly=<регвыр> — выбор, -PscenarioRealChunks — настоящая загрузка)
cd mod && ./gradlew runScenarioRecord     # записать эталон траекторий заново (сдвиг — объяснить в PR по сценариям)
tools/client_scenario.sh nuke             # клиент без окна: mod/run/scenario/screenshots/*.png, audio.wav, logs
tools/deploy.sh                           # jar → dist/ (для друзей) и mods/ инстанса без автообновления сборки
python3 tools/logscan.py [--since 18:30]  # после игры: ошибки мода, удары, подрывы, Sable
git commit
```
Скрипты с пакетами (numpy, scipy, soundfile, Pillow: звуки, текстуры, модели, трейлер) объявляют их сами блоком
`# /// script` (PEP 723) — запуск `uv run tools/<скрипт>.py`, в системный Python ничего не ставить.
Моды для запусков (`run/*/mods`) копируются из инстанса задачами `copyRuntimeMods_*`; путь — `MC_DIR` или по умолчанию.
Без инстанса (облачная сессия, CI): `python3 tools/fetch_runtime_mods.py` → `./gradlew runGameTestServer -PmcModsDir=run/ci-mods`
(Java 21 в облаке есть, сеть к NeoForge/Mojang/Parchment/Modrinth открыта); `-PwithLithium` — GameTest ещё и
с Lithium, как у хоста (в jar и `mods.toml` его нет).
CI (GitHub Actions, репозиторий публичный) гоняет то же один раз на коммит: push в `main` и PR (ветка без PR CI
не запускает — PR открывать сразу, черновиком); jar — артефакт `airstrike-jar`. Проверяется то, что изменилось
(задача «Что изменилось»): правка только `tools/` (кроме `fetch_runtime_mods.py`, `paths.py`), `docs/`, `*.md` мод не
собирает и GameTest не гоняет; `pack/` и `tools/prism_instance.py` — только задача «Сборка модов» (индекс packwiz свежий,
`.mrpack` и экземпляр Prism собираются);
`mod/`, CI и незнакомые пути — проверка целиком, ручной запуск (релиз) — всегда целиком.
GameTest идёт частями на шести машинах (`-PgametestShard=i/n`, `GameTestShards`: партия целиком в одной части, части
равняются по `gametest-durations.json`; таблицу освежает `tools/gametest_durations.py` по логам частей, когда части
заметно разошлись по времени). Слияние решает задача «Итог»: падает, если упала или отменена любая нужная проверка.
Прогона с Lithium в CI нет: мод не лезет туда, что Lithium подменяет (тик блок-сущностей, цикл `Explosion.explode`), —
`-PwithLithium` остаётся для проверки совместимости руками.
Релиз: поднять `mod_version`, написать `docs/releases/<версия>.md`, влить в `main` и запустить `build` вручную на `main`
с `release=true` — после всех проверок workflow выпускает `v<версия>` с jar (оттуда его берут друзья). Если `main` ушёл
вперёд от проверенного в игре коммита — ветка `claude/release-…` от этого коммита с одними заметками, запуск на ней.
PR сборки с jar выпуска — после выпуска: `pack/` на `main` игроки с автообновлением ставят при следующем запуске.
Версию протокола (`AirstrikeNetwork.PROTOCOL`) поднимает PR, который меняет формат пакетов или данных сущностей; релиз,
у которого поведение или ключи языка отличаются от прошлого выданного jar, поднимает её сам, если за выпуск её ещё
не подняли: старый jar не должен заходить к новому хосту (NeoForge тогда говорит «разные версии мода»).

## Архитектура (пакеты `ua.zentix.airstrike`)
Здесь — карта пакетов; как они устроены — в файлах правил (список в конце).
- `Airstrike` — регистрации и подписки на события (игровая шина); `AirstrikeConfig` — SERVER (мир) и CLIENT.
- `registry/` — сущности, предметы (пульт, счётчик Гейгера, тринитит, боеприпасы, ЗРК и зенитная ракета), блоки,
  блок-сущности, эффекты, attachments, звуки, теги, типы урона, компоненты данных (`Loadout` в пульте), вкладка творчества.
- `strike/` — приказы и права, боеприпасы из инвентаря (`Munitions`), второй ключ ядерного удара не оператора (`NuclearKeys`), пуск, залпы, маршрут оператора (`Waypoints`, устройство — в `entity.md`), место
  пусковой, полёт вне мира, загрузка районов и места входа игрока, статус полётов, цена попаданий, дальние пути
  снарядов игрокам. **Паспорт оружия** `WeaponSpec` (`WeaponType.spec()`):
  новое число, которым оружие отличается, — в паспорт, а не константой в сущности и не `switch` по оружию.
  `target/` — цели и прицел; `compat/SubLevels` — вся связь с Sable.
- `entity/` — снаряды, пусковая, сброшенный ускоритель, обломки; `guidance/` — повороты, маршрут, баллистика, круг
  барража, падение бомбы, запас хода, автопилоты шахеда и ракеты.
- `work/` — общий бюджет тяжёлой работы на тик сервера: полосы попаданий, ядерки и блэкаута.
- `warhead/` — взрыв боевой части по частям (`StagedExplosion`), стёкла, обломки, осыпание воронки.
- `nuclear/` — ядерный удар: физика `model/`, подрыв, руины `world/` (снимки, планы в фоне, зона за волной), радиация.
- `net/` — `S2C`/`C2S` пакеты; `ClientHooks` — интерфейс, который реализует клиент (сервер не грузит клиентские классы).
- `command/AirstrikeCommand` — `/airstrike` (то же, что пульт, плюс ядерка, радиация, выдача); `item/` — пульт
  (`DesignatorItem`: бинокль, экран), счётчик Гейгера и боеприпасы (`MunitionItem`: рецепты — `data/airstrike/recipe`, с Create
  и ванильной заменой по условию `neoforge:mod_loaded`); `util/` — `Local` (локальные координаты «^ ^ ^»),
  `Particles` (разброс частиц как у команды `particle`), `Terrain` (готовность чанка и высота без ожидания загрузки; «где земля» — только `Terrain.estimate`: высота и источник `CHUNK`/`CEILING`/`CLIENT_MAP`/`GENERATOR`/`SEA`/`UNKNOWN`, вызывающий выбирает допустимые — `Allowed.CHUNK` в мире, `FLIGHT` вне мира, `ORDER` для приказа; прямых `getBaseHeight`/`getSeaLevel` вне `Terrain` нет; `Terrain.height` — источник `CHUNK` без выбора для кода, который сам знает, что чанк готов: `LaunchSite`, взрывы `Warheads`, `nuclear/world`, площадка МБР за игроком в `NuclearStrikes`), `Nbt` (векторы в NBT); миксины (подводные камни — `server-chunks.md`, `sable.md`, `nuclear-world.md`):
  `mixin/sable/` и `mixin/net/` (`PlayerChunkSenderMixin` — чанк без руин не уходит игроку); выход из мира без зависания в выгрузке — `util/StopDrain` (без миксина).
- Состояние сервера, которое не сохраняется, — несохраняемые attachments NeoForge (мира: `StrikeWorld`, `NuclearWorld`, `CraterFalls`, `DefenseWorld`; игрока:
  пауза между пусками, «HUD полётов показан»), а не статические карты: статика переживает смену мира в одиночной игре.
- `client/` — модели снарядов, дальняя картинка, звук, свои частицы и слой эффектов, HUD, камера снаряда, бинокль,
  пульт и карта наведения, повтор Flashback, ядерная картинка.
- `grid/` — блэкаут: сеть и кварталы, каскады отключений, лампы-двойники без света.
- `defense/` — ПВО: блок ЗРК (`SamBlock`/`SamBlockEntity`: запас ракет, направляющие, перезарядка), радар (`Radar`:
  только снаряды мода, заметность — `WeaponSpec.Signature` в паспорте), огонь (`FireControl`), тревога (`AirAlert`),
  полёт зенитной ракеты без мира (`Interceptor`, `DefenseWorld` — несохраняемый attachment мира).
- `legacy/LegacyMigration` — переезд со старого датапака: выключает `file/airstrike`/`file/shahed`, переносит
  `storage airstrike:cfg` в конфиг, убирает objectives и старые сущности с тегами.

## Единицы и масштаб
- Блок = метр. Скорости снарядов — блоки/тик (шахед 2.1, барражирующий 1.6 и в пике 4, ракета 4 и в пике 5 (медленнее настоящей, чтобы подлёт было видно), B-2 12, МБР до 25, зенитная ракета ЗРК до 14; РСЗО — по баллистике,
  g = 0.0245 блока/тик²). Звук — 17.15 блока/тик.
- `WeaponType.id` = порядковый номер в перечислении (клиент берёт `values()[id]`): новое оружие — только в конец;
  порядок в пульте и в бинокле — `WeaponType.menu()`.
- Ядерная модель — в метрах, секундах, килотоннах; `Detonation.blocks/metres` переводят с учётом `effects_scale`
  (`scale`): расстояния × scale, время фронта модели × scale. Фронт в игре — `FrontProfile` (`Detonation.arrivalTicks/frontRadius`):
  до двух радиусов шара (не дальше 200 блоков) — как у модели, дальше плавно до 3 блоков за тик к 600 блокам (при 17
  блоках за тик стена пыли проходила прорисовку за доли секунды), за краем стены пыли (0.3 psi) — только звук, со
  скоростью звука; стена пыли, мгла, звук, урон, отброс и руины (по центру чанка) берут время прихода только оттуда.
  Игровые часы осадков: 1000 тиков = 1 час.

## Общие правила кода и проверок
- **Ничего не читать в незагруженных чанках из тика**: `getBlockState`, `clip`, ванильный `explode` и даже
  `TicketController.forceChunk` NeoForge грузят/генерируют чанк сразу — сервер вставал на 5–6 с. `hasChunk`/`isLoaded`
  верны и для чанка, который ещё грузится, а `getHeight`/`getBlockState` на нём ждут в `managedBlock` (до 400 мс):
  проверять готовность через `getChunkNow` (`util/Terrain`). Для ядерного удара — ванильный `TicketType`
  (`NuclearTickets`, грузит в фоне).
- `Locale.ROOT` для чисел в командах: у Артёма русская локаль, `String.format("%.1f")` даёт запятую.
- Тяжёлые задачи на ноутбуке Артёма — через `tools/laptop_job.sh` (своя служба systemd, не группа приложения Claude:
  однажды общая группа уронила само приложение). Одновременно — одна задача со всей сборкой (≈12 ГБ) или стенд,
  лёгкие — рядом, если по сумме помещаются в 32 ГБ; прожорливое чинится в коде, а не пределами памяти. `/tmp` там —
  tmpfs в ОЗУ: большие файлы (клоны, копии инстанса, кадры) — на диске, например в `mod/run/` (в .gitignore).
- Ничто из проверок не должно доходить до экрана и колонок Артёма: клиенты — только через `tools/nested_kwin.sh`
  (`--virtual`: внеэкранный буфер на видеокарте, окна на рабочем столе нет; `PIPEWIRE_REMOTE`/`PULSE_SERVER` указывают
  на несуществующие сокеты — OpenAL не открывает звук хоста). Звук сценария пишется драйвером «wave» в файл, трейлер
  собирает звук из журнала. Путь без KWin (облако, `xvfb-run`) закрывает звук так же.

## Файлы правил `.claude/rules/`
- `tools.md` — подробная раскладка проекта и что умеет каждый скрипт `tools/`.
- `strike.md` — `strike/`, `target/`: приказы, паспорт оружия, пуск, полёт вне мира, районы, итоги попаданий.
- `entity.md` — `entity/`, `guidance/`: полёт, маршрут, автопилоты; снаряд вне мира, отслеживание сущностей клиентом.
- `work.md` — `work/`: полосы бюджета, очередь единиц; массовый урон — единицами.
- `warhead.md` — `warhead/`: взрыв по шагам, стёкла, осыпание; частицы ванильного взрыва, миксины сборки на взрыве.
- `nuclear.md` — `nuclear/` (без руин), клиентская ядерка: модель, подрыв, радиация, часы и пакет подрыва.
- `nuclear-world.md` — `nuclear/world/`: руины, подготовка, зона за волной, запись в секции, отдача чанков игроку.
- `grid.md` — `grid/`: блэкаут, лампы в палитре, свет чанка с диска, ресурсы двойников.
- `defense.md` — `defense/`: ЗРК, радар, огонь, тревога, полёт зенитной ракеты; что можно и нельзя брать целью.
- `server-chunks.md` — загрузка и тикеты чанков, выход из мира (`StopDrain`), события чанков, сущности и блок-сущности.
- `sable.md` — Sable: падение при расколе аппарата, чтение соседей на каждое изменение блока.
- `dh.md` — Distant Horizons: рельеф карты через API, LOD чанков вне мира, утечка миров.
- `client.md` — `client/`: устройство клиента, карты высот клиента, Iris и `AFTER_LEVEL`, векторы камеры.
- `client-fx.md` — свои частицы, слой эффектов, места частиц, шлейф-лента, шейдер с отсечением альфы.
- `client-models.md` — модели снарядов OBJ, рисование путём сущностей, настоящая величина.
- `client-sound.md` — звук: фильтры OpenAL, моно, громкость и петли моторов.
- `replay.md` — повтор Flashback: перемотка, разовые события, метки тика.

## Окружение
- NeoForge 21.1.250, Minecraft 1.21.1. Хост играет в своей сборке «Airstrike Pack» (`pack/`, 53 мода), прежний
  инстанс «All of Create Aeronautics» (~217 модов) лежит рядом. Мультиплеер: хост открывает свой мир друзьям;
  jar мода нужен всем (сервер и клиенты).
- Важные моды: Create 6.0.10, **Create Aeronautics 1.3.2 + Sable 2.0.5** (аппараты — «sub-levels», блоки живут
  в далёком «плоте», их ломает ванильный взрыв через миксин Sable), Sodium, **Iris с шейдерами у хоста**, Distant Horizons,
  Flashback, Essential.

## Не сделано / идеи
- Барражирующий сам ищет цель на круге (сейчас её выбирает оператор из камеры).
- Упреждение шахеда и ракеты по идущей цели (`Dive.intercept`, как у «Ланцета» в пике) — новое поведение наведения,
  отдельным PR после выпуска (в общий автопилот не вошло: перенос законов — побитно тот же полёт).
- Атака ракеты не видит рельеф между снарядом и целью: горка — до цели+32 от высоты цели. Цель на дне глубокого карьера
  или за холмом после перенацеливания — ракета задевает склон или край за десятки блоков до цели
  (`AutopilotPropertiesTest`: «рельеф закрывает цель на атаке»). Шахед пике с 18° ждёт свободной прямой до цели
  (`Craft.clearAlong`), но не дольше, чем нос успевает довернуть: высотку ближе ~45 блоков к цели и цель под крышей
  он не обходит (`DroneDiveTest`).
