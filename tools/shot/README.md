# Съёмка по сцене (`tools/shot`)

Камера плана решается до игры: сцена (карта рамки, пути снарядов, удары, дым, туман края прорисовки, облака) — в
памяти, камера — путь тела (FPV, кинодрон, оператор с камерой в руках, штатив, следящая камера пуска), который лучше
всех по одной мере, черновой кадр — лучами по блокам за доли секунды. Игра (вывод `ReplayFilm`, съёмка replayscan)
только рисует готовый путь, а её проверка кадров сверяется с тем, что мера обещала (`predicted.jsonl`).

Почему так — записка `/mnt/project-files/filming-rethink/` (13.10.2026).

```sh
uv run tools/shot/shot.py plan <план>.events.jsonl --regions <мир>/region --out <папка> [--styles fpv,tripod]
uv run tools/shot/shot.py demo --out <папка>          # тестовый квартал без карты
uv run tools/shot/shot.py check <трейлер>/render/*/*/qa.jsonl --regions <мир>/region --out <папка>  # мера ↔ вывод
uv run --with numpy --with scipy --with pillow python -m unittest discover -s tools/shot/tests
```

- Объект плана — по `trailer_shots.json` (те же правила, что `Coverage` и `Rig` трейлера: `impact:W[@x,z][#n]`,
  `first:W`, `framed:W`, `flight:W`, `launch:W@x,z[,r]`, `nuke`; полёт — тот, что камера сценария держит в кадре дольше
  всех, при равенстве — крупнее, из равных — первый по появлению), иначе `--subject` (одно на все планы или
  `p32=track:3,p12=…`), иначе `auto`. `track:<номер>` — путь журнала по номеру: тот, что ведёт вывод, когда `check`
  пишет «другой объект»; у плана со своим правилом оно остаётся (полёт — без удара), выбор — из этого пути. Выбор — по всему окну `start`…`end` журнала, как у трейлера (`span` плана режет только окно
  проверки), у журнала до очереди мест (`--shown`) — по сглаженным местам; удар — с запасом 20 тиков. Там же `need`
  плана (`Coverage.Need` без мотора) и, если нужно, `styles` — тела по замыслу.
- Мера (`shotlib/solve.py: evaluate`), меньше — лучше. Главное в ней — то, что решает проверка кадров вывода
  (`FrameQa.verdict`): доли кадров до удара, за последнюю секунду и у удара, где объект в кадре, виден (не за блоками,
  дымом, туманом и облаками) и не мельче нормы, против `need` плана с запасом 0,1. Сверх нужного — как снимает человек:
  объект держится в кадре (у FPV слабее: он летит туда, куда смотрит), композиция, размер; камера не в блоках и с
  воздухом вокруг, на высоте своего тела; скорость, разгон, рывок и повороты взгляда в пределах тела; у FPV крен и кивок
  — из ускорения, крен не больше 20° без счёта и не качается, взгляд от курса — до 20° на подлёте, 60° у удара, 30° после,
  после удара смотрит всё больше вперёд по курсу; низ кадра — не в чанках, которых нет. `own` в отчёте — камера
  сценария той же мерой.
- Замысел взгляда — два, какой лучше, решает мера: вести снаряд или держать место удара (снаряд сам входит в кадр,
  последнюю секунду кадр — между ним и местом).
- Какую камеру выводить: первое тело по замыслу (`styles` плана, иначе FPV, дрон, штатив…), которое проходит проверку
  с запасом 0,05 и показывает объект почти как лучшее из прошедших (запас — не меньше лучшего без 0,2, доля кадров
  «в кадре и виден» — без 0,15); не проходит ни одно — то, которому меньше всех не хватает.
- Поиск — кросс-энтропийный по опорным точкам B-сплайна: семена по телу (проходы с 16 курсов и трёх расстояний — у
  FPV ближе всего к удару через 24 тика после него, места штатива по кругу, погоня), лучшие сгибаются пробами вокруг
  лучшего.
- Выдача плана: `<план>/<тело>/camera.jsonl` — поза на тик повтора (`t`, `pos`, `yaw`, `pitch`, `roll`, `fov` по
  вертикали; углы — как у Minecraft: курс 0 — юг, тангаж плюс — вниз, крен плюс — влево), `path-camera.json` — камера
  `path` плана replayscan, `predicted.jsonl`, `report.json`, `summary.txt`; с `--previs` — `sheet.jpg`, `previs.mp4`.
- `check` — сверка меры с проверкой кадров вывода (`FrameQa`): камера каждого кадра из `qa.jsonl`, объект — тот же,
  что у плана; по кадрам — совпало ли «в кадре» и «виден», место в кадре, доля кадра, кто из двоих видит блоки или дым
  на линии, и итог плана (доли до удара, за секунду, у удара) мерой и выводом. 13.10 на 7032 кадрах Zearth: «в кадре»
  совпало в 91 % (на свежем выводе — 95 %), «виден» — в 89 % (93 %); после правок — 98 % и 97 % на свежем выводе.
  Ещё — где объект у клиента вывода: место сущности обратно из места в кадре и доли кадра, против места журнала
  («объект от журнала», блоки). Дальше 8 блоков в десятой части кадров — «ЖУРНАЛ СБИТ»: журнал писал клиент, который
  показывал снаряд не там, где вывод (film-war4 на 52d661a при отстающем сервере), и камеру плана по нему не ставить.
  Вывод пишет и свой журнал — клиентом, который рисует кадры (`<кандидат>/<план>.events.jsonl` рядом с `qa.jsonl`):
  `check` берёт его, если он есть (`--replays` — журнал записи), а `plan` по нему ставит камеру следующего вывода.
  Объект и тогда выбирается по журналу записи и его камере сценария, как у вывода (`Rig`), а места — из журнала вывода
  по UUID снаряда: номера путей у журналов свои, а камера в журнале вывода — уже камера плана (14.10: по ней правило
  «дольше всех в кадре» брало другой снаряд у четырёх планов, прошедших вывод). Удар объекта у вывода не там или не
  тогда, что в журнале записи, — «УДАР У ВЫВОДА ДРУГОЙ»: камера плана ставилась по удару записи. У камеры по сцене
  (`<тело>-planned`) — ещё и камера вывода против камеры плана (`<трейлер>/planned/<план>.camera.jsonl`): у `-raw` она
  должна совпасть («КАМЕРА НЕ ПО ПЛАНУ» — дальше полублока или 3° по медиане, у удара — блока или 5°, кадры вне плана).
  14.10, 15 камер по сцене на ноутбуке (film-war4 и film-war2): 14 прошли вывод; у 11 мера и вывод совпали по кадрам
  на 98–100 %.
- Дым в мере — тот, что считает проверка кадров (`FxPool`): столбы ударов (модель `Plume` превью), клубы объёма у
  горящего ускорителя (клуб за тик, полминуты висит: залп «Града» — веер дуг над пусковой; у МБР — весь полёт) и облако
  старта МБР. Клубы кладёт клиент, у которого есть сущность снаряда, — только тики журнала, где место снаряда от
  сущности (шестое поле строки `f`), а не от сервера. Ветер сносит клуб по тику частицы: облако старта (сопротивление
  0,95) — вдвое быстрее следа (0,9). Лента шлейфа частицами не считается — и здесь тоже.
- Журнал, записанный до очереди мест мода (film-war2 и раньше), — с `--shown 1.5`: пути снарядов сглаживаются, как их
  показывает повтор (`Shown` трейлера).
- Карта рамки (`world.npz`) — данные карты: остаётся на машине, где лежит мир (Zearth наружу не выносится; наружу —
  `summary.txt` и черновые кадры).

Модули `shotlib`: `world` — блоки из файлов регионов (роды: воздух, непрозрачный, листва и стекло, вода, неизвестный
чанк), `scene` — журнал EventLog, дым ударов и шлейфы ускорителей (гауссовы клубы, свет сквозь них — точным интегралом), `subject` — выбор
объекта и окна, `camera` — углы и проекция Minecraft, тела камер, `solve` — мера и поиск, `previs` — черновой кадр,
`export` — выдача, `demo` — тестовый квартал.
